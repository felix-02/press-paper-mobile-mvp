# Presspaper for Android and iOS

This repository is a mobile-only React Native application for Android and iOS, built with Expo SDK 55, React Navigation, and Supabase. The application and npm commands live at the repository root. Supabase migrations and AI functions are retained in `supabase/`; an optional, minimal backend for public shared links lives in `services/share/`.

See [PARITY.md](./PARITY.md) for the workflow inventory, backend contracts, and the device acceptance checklist. Source implementation and successful JavaScript exports do not establish complete device or staging parity.

## Local development

Use Node 22.18 or newer in the supported Node 22/24 lines and npm. From the repository root:

```sh
npm ci
cp .env.example .env.local
```

Set the following in the ignored `.env.local` or your build environment:

```dotenv
EXPO_PUBLIC_SUPABASE_URL=https://your-development-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-browser-anon-key
EXPO_PUBLIC_SITE_URL=https://presspaper.ai
```

`EXPO_PUBLIC_SITE_URL` is optional; it selects the public share-link service used in shared release URLs. Use an HTTPS origin you control. Use your existing Supabase project to preserve accounts, releases, and engagement data. Use `EXPO_PUBLIC_*` variables for the native app. Expo embeds `EXPO_PUBLIC_*` values in application bundles: never use a service-role, Gemini, or administrative key here.

Apply the existing Supabase migrations through `0018` to the chosen development project. Configure the `org-media` bucket/policies as defined by the repository migrations. Deploy the existing `summarize` and `translate` Edge Functions only if AI features are required; their Gemini key remains server-side. See [SUPABASE_SETUP.md](./SUPABASE_SETUP.md).

```sh
npm start
```

Use a development build for reliable app-scheme authentication and invitations. To compile locally:

```sh
npm run android
```

Android requires a configured Android SDK, JDK and emulator or attached device. For iOS, use macOS with Xcode, CocoaPods and an iOS simulator/device:

```sh
npm run ios
```

Expo generates native projects from `app.json` when using these commands. Generated `android/` and `ios/` directories are ignored. A Linux cloud workspace can install dependencies and export both JavaScript bundles, but cannot run the iOS simulator or compile with Xcode.

## Authentication and links

The application scheme is `presspaper`. Team and institution invitations generated by the app use this scheme. Add these allowed redirect URLs to the development project's Supabase Auth URL configuration:

```text
presspaper://auth/callback
presspaper://reset-password
```

Test confirmation and password-recovery links on a development or signed build. Session restoration uses native storage; app foreground/background transitions control token refresh. Redirect handling must be tested both when the application is closed and when it is already running.

Native navigation preserves the browser path vocabulary for release, institution, watchlist, and invitation destinations, including `/release/:id`, `/r/:id`, `/institution/:slug`, `/watchlist/:id`, `/join/:token`, and `/institution-invite/:token`. For example, a native release link is `presspaper://release/<uuid>`. Invitation acceptance still requires the confirmed invited email; changing the client does not bypass expiry, single-use, or role checks.

Sharing uses public HTTPS web links so recipients without the app can read the existing share page. Opening your HTTPS domain directly in the installed app requires Apple associated domains/AASA and Android verified App Links/assetlinks configuration. Those domain associations are not provisioned by this repository. Configure them with the actual production domain and signed application identifiers before claiming universal-link support.

## Validation

Run from the repository root:

```sh
npm run typecheck
npm test
npm run export
```

The test command runs boundary tests for authentication links, workspace selection, rich-text sanitization and formatting, plus native interaction tests for authentication, invitation routing and publishing permissions/error handling. Export validates bundling; it does not produce installable signed applications. Follow [PARITY.md](./PARITY.md) for account-role, database, cross-client, and physical-device checks.

The browser application, Vite tooling and browser-only tests have been removed. The native suites include the retained database authorization-contract checks and public shared-link safety checks.

## Installable builds

`eas.json` supplies development, internal preview, and production profiles. Before using EAS Build, select your Expo organisation/project, confirm ownership of `ai.presspaper.mobile` (or change both platform identifiers), configure the public Supabase build variables, and provide signing credentials through Expo/Apple/Google's secure flows.

```sh
npx eas-cli build --platform android --profile preview
npx eas-cli build --platform ios --profile preview
```

The preview Android build is an APK. Internal iOS distribution requires Apple provisioning for registered devices. Production builds use the `production` profile; store submission, review, privacy disclosures, application icons/screenshots, and production domain associations remain release tasks. No store submission or environment publication is performed by implementing this application.

## Repository layout

- `App.tsx` and navigation code select role-specific native workspaces and deep-link destinations.
- `src/screens/` contains auth, reader, institution, and platform administration screens.
- `src/auth/`, `src/lib/`, and `src/store/` adapt existing Supabase contracts and business behavior to native lifecycle/storage APIs.
- `src/ui.tsx` contains native layout, form, button, and appearance primitives.
- `supabase/` and `presspaper_all_migrations.sql` define the shared backend.
- `services/share/` serves public article previews for links shared from the app.

The native application uses the existing Supabase schema and authorization contracts. Keep migrations and client behavior in sync. Runtime business data is never replaced with samples when Supabase is unavailable.
